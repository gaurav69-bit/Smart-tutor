# ST-64 — Phase 1 account user stories (proposed)
- As a student, I want to register so that I can access tutoring services. Acceptance: valid inputs accepted; duplicate email rejected; email verification required.
- As a tutor, I want to register so that I can offer lessons. Acceptance: tutor role captured; approval requirements agreed with backend owner.
- As a user, I want to log in securely. Acceptance: credentials verified server-side; unverified/inactive users blocked; OTP if required by team.
- As a user, I want useful validation messages. Acceptance: invalid email, missing fields and unsupported roles return clear errors without revealing credentials.
- As a user, I want to log out. Acceptance: session/token invalidated by production backend.
These are draft acceptance criteria for team review, not proof that the live application meets them.
